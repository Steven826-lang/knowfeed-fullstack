## 0. 总览：功能健康度地图

评分标准：1=需求本身没想清楚，2=实现残缺/失真，3=可用但平庸，4=良好，5=优秀。

### 跨模块系统性缺陷（比单功能更重要）

1. **社区与微课"两张皮"**（P0 之根）：tick/world_init 的 prompt 只拿到 topic 标题 + 哈希 concept_id，agent 不知道用户在学什么；微课完成不触发任何社区事件；spec §11 设想的"学完回社区，agent 围绕刚学的内容讨论"没有实现路径。
2. **激励信号失真三连**：答案恒 a（quiz 失效）→ 答错也涨分（掌握度失真）→ streak 计数器化（连续性失真）。Duolingo 式激励链目前只有形没有义。
3. **数据产生但不消费**模式反复出现：completionFeedback、reviewQueue、freeResponse、targetDepth/preferredTone、sourceUrls、briefing、follows——每个数据字段都缺"用户可感知出口"。
4. **无通知体系**：用户发帖后离开就与服务断联，没有任何召回通道。

## 1. P0 功能 PID 卡（先修这些）

### PID-L5：答题与反馈

- **定义与价值**：一道判断题检验理解 + 即时解析，把"刷过"变成"学会"，是微课的学习有效性根基。
- **现状**：默认选中第一项；选中即泄底 feedback；提交后直接跳走从不告诉对错；正确答案恒为 choice-a（`curriculumValidator.ts:131-137`）；干扰项 C 每课相同固定文案。
- **需求缺陷**：quiz 作为掌握度信号基本失效；用户闭眼点"完成"就是满分路径。
- **打磨方向**：
  1. validator 生成选项时随机打乱正确答案位置，正确答案 id 不再恒定
  2. 取消默认选中；两段式提交：先选 → 点"查看答案" → 判定页（揭示正解 + 每条选项的解析）
  3. 答错给一次"看提示重答"机会，重答对得半分
  4. 干扰项由 LLM 按 misconception 生成（validator 已有 misconceptionToFix 字段未被用于出题）
- **沉迷设计**：判定瞬间是最强即时反馈点（心流的前提），解析页给"你超过了 X% 的学习者"式轻量社会比较（可选、可关）。
- **验收指标**：正确答案位置均匀分布；用户无法在提交前看到任何 feedback；答错路径有独立文案与补偿内容。

### PID-L6：掌握度 / XP / streak

- **定义与价值**：低压力坚持机制——掌握度驱动解锁与任务推进，XP 与 streak 提供即时奖励与连续性。
- **现状**：streak 无任何日期逻辑（完成一节课 +1，初始值 1）；解锁只拦地图按钮，feed chips 可绕过（`HomeFeed.tsx:278-288`）；单次满分 +44 < 70 推进线，D2 任务仍是 D1 同一节课。
- **需求缺陷**：streak 是完成计数器却占据顶栏最显眼位置；7 天路径在一天一课用法下 7 天走不完。
- **打磨方向**：
  1. streak 改为自然日驱动（比较 completedAt 日期），初始 0，断日清零，加 streak freeze 道具（每周送 1 个）
  2. mission 推进线从 70 降到单次完课可达（如 40），保证 D2 的任务是第 2 课
  3. 所有入课入口统一走解锁校验
  4. mastery 加满后与重复刷分解耦：已满分概念再完课只记复习记录不涨 mastery
- **沉迷设计**：真 streak + freeze 是 Duolingo 验证过的最强留存机制（损失厌恶）；注意伦理红线：不做 guilt-trip 文案（"你要放弃吗"式禁用）。
- **验收指标**：D2 今日任务 = 第 2 个概念；连续两天完课 streak=2 且隔天不清零需 freeze；feed chips 与地图解锁行为一致。

### PID-L7：复习队列

- **定义与价值**：对抗遗忘、制造回访理由（PRD 已承诺但从未兑现）。
- **现状**：写入端存在（完成的概念置顶、截断 4 个），读取端只有 prompt 载荷，**全库无任何 UI 渲染**。
- **需求缺陷**：本质是"最近完成的 4 个概念"历史栈，不是复习队列：无到期、无间隔、无复习任务。
- **打磨方向**：
  1. 数据结构从 `string[]` 升级为 `{conceptId, dueAt, stage}[]`，间隔 1/3/7 天递增
  2. feed 顶部"今日复习"卡（优先级高于新课），到期才出现
  3. 复习形式 = 新 quiz 变体（重生成，答案位置再打乱）+ 一句回忆
  4. 复习完成显示"记忆加固"反馈并从队列移除
- **沉迷设计**：间隔重复本身是最强学习有效性证据；到期提醒（PWA push）是合规的外部触发。
- **验收指标**：到期复习卡可见；完成复习后队列更新；streak 与复习分别计数。

### PID-L9：AI 分身草稿（费曼输出仪式）

- **定义与价值**：学完→输出的转化器，本产品的差异化记忆点；也是"门徒效应"（教别人显著提升理解保持，Cohen's d=0.87，有实证支撑）的产品化。
- **现状**：草稿课前生成，输入只有 lesson+post，**不含用户的 quiz 结果与 freeResponse**；handoff 卡宣称"基于这次学习生成"与事实不符；批准只移入 `approvedShadowPosts` 陈列，不进社区、AI 居民不可见。
- **需求缺陷**：发布到虚空——闭环断在最后一公里；freeResponse 提交后即弃。
- **打磨方向**（这是 PID 卡里最值得做的一张）：
  1. 草稿改为**课后**生成，输入 = lesson + 用户 quiz 对错 + freeResponse 原话（"用你的原话改写成一条社区发言"）
  2. 批准 = 真实发布到社区（走 `createCommunityPost`），触发 mini-tick，AI 居民来追问/挑刺/点赞
  3. handoff 卡前置草稿入口（"你的分身写好了这条发言 →"），不必摸到设置页
  4. 批准时自动保存当前编辑（修编辑陷阱）
- **沉迷设计**：输出即学习、被回应即奖励（tribe 型可变奖励）；AI 居民对你输出的追问制造"被接住"的保证感——这是 10 个沉迷候选里"最正"的机制（低伦理风险 + 高学习有效性 + 高差异化）。
- **验收指标**：批准后 30-90 秒内至少 1 条 AI 居民回应出现在该帖；草稿文本包含用户 freeResponse 的影子；发布记录可在"我的"页回看。

### PID-C5：点赞 / 点踩

- **定义与价值**：最轻量态度表达，同时是推荐热度信号与 agent 信念演化的输入。
- **现状**：后端完整（upsert 幂等、改票支持），**前端从未调用**；feed 赞同按钮 disabled；详情页全是本地假 toggle；无点踩 UI；用户 reaction 不回写 heat/karma——热度信号 100% 来自 agent 互投，社区热度是自嗨闭环。
- **打磨方向**：
  1. 前端接通 `/reactions`（乐观更新 + 失败回滚）
  2. 后端 `create_reaction` 补 heat/karma 回写（对齐 agent reaction 行为）
  3. 详情页加点踩；用户 reaction 作为 belief `update_trust` 输入（你点赞的居民更信任你）
- **验收指标**：刷新后点赞状态保持；帖子热度因用户点赞实时变化；agent 对被用户点赞的内容有信念响应。

### PID-C9/C10：Tick 演化的 concept 同步 + 简报渲染（两张皮修复包）

- **定义与价值**：社区围绕用户"正在学的东西"演化，是社区与学习主线缝合的根。
- **现状**：`worlds.current_concept_id` 创建后永不更新；tick prompt 里"当前概念"是哈希 id（agent 不知道在讨论什么）；catchup briefing 后端完整产出、前端从不渲染。
- **打磨方向**：
  1. 微课完成后调 `POST /worlds/{id}/advance`（新增或复用旧 advance 路由）同步 current_concept_id，并显式触发一次带 lesson_snippet 的演化（`build_observation_text` 已支持该参数但没人传）
  2. world 创建/推进时把 concept_id→title 映射传入所有 prompt 路径
  3. feed 顶部渲染"你不在的时候"简报卡（deep 档）：N 个新热帖、M 条相关讨论、K 个 delta 瞬间，可点击跳帖
- **沉迷设计**：简报升级为**叙事版**——从"3 个新热帖"升级为"Mara 和 Chen 为了你上次那个观点吵起来了"（Zeigarnik 悬念 + 好奇心缺口，是把"离开"变成"攒剧情"的独特机制，伦理风险低，代码已铺好一半）。
- **验收指标**：学到第 3 个概念后社区新帖围绕第 3 个概念；24h+ 回归时简报卡可见且可点击；简报文案含具体居民与事件而非纯数字。

### PID-C1：推荐 Feed 收尾

- **现状**：无限滚动未实现（nextCursor 已映射没人用）、手动刷新按钮未接（API 已存在）、推荐理由渲染原始 concept_id 哈希、在线人数是编造数字（帖数×3+8）。
- **打磨方向**：接 cursor 无限滚动（每 10 帖重算推荐分，后端已支持）；推荐理由映射 concept 标题；presence 角标改真实口径（近 N 分钟活跃 agent 数）或删除；加"刷新社区"按钮。
- **验收指标**：下滑可加载第 2 页且不重复；推荐理由可读（"和你正在学的『私钥控制权』相关"）；无编造数字。

## 2. P1 功能 PID 卡（让体验上一档）

### PID-L1：Onboarding 采集
- **核心缺陷**：targetDepth/preferredTone 采集后全代码库无任何规则引用；生成后不可修改只能全量重置。
- **打磨**：深度/语气写成 planner 与 lesson 生成的显性规则（深度驱动概念颗粒度与 quiz 难度，语气驱动评论调性）；增加"微调目标/时长"入口代替重置；出海前把语言做成选项。

### PID-L2：路径规划
- **核心缺陷**：planner 草案 ≥3 天即接受，不足 7 天静默补齐（标题为"{topic} 第 N 步"的充数内容，无标识）；每天只取 concepts[0]，多概念被扔；sourceUrls 解析了但 Concept 类型没这字段。
- **打磨**：不足 7 天时明示"AI 未排满，已补基础条目"或重试；Concept 保留 sourceUrls/whyNow；按 targetDepth 产出不同骨架（casual 平直 7 点，strategic 概念+案例+判断混合）。

### PID-L3：路径预览
- **核心缺陷**：是"收据"不是"预览"——全程只读，不能换/重排/重新生成；个性化理由不可见。
- **打磨**：每天卡片加"学完你能看懂哪种争论"（feedHook/whyNow 数据已存在未使用）+"为你而排"理由 chip；支持单日重新生成；显示预计总时长与完成日；预览入口常驻地图顶部。
- **沉迷设计**：禀赋进度效应——Day 1 显示"已解锁"制造进度预赠感（洗车卡实验：预盖 2 章完成率 34% vs 19%）。

### PID-L4：微课堂
- **核心缺陷**：`completionFeedback` 生成与校验都强制要求，但任何组件都不渲染（每节课最该被看到的一句话被丢弃）；微课没有回头看价值；中途退出无保存。
- **打磨**：completionFeedback 做成完成页主视觉（替代干巴巴的"+X XP"）；完成卡加前后对照（抽 1-2 条高热评论标注"学完这节你能看懂这条在争什么"，零额外生成成本）；已完成课程显示完成态与历史作答。
- **沉迷设计**：完成卡加"明日悬念"（"明天：{下一概念}，社区里 {某居民} 已经开始吵了"）。

### PID-C4：评论/回复
- **核心缺陷**：轮询 30s 超时 vs NewPost 承诺 30-90s；超时后静默停止无任何提示。
- **打磨**：轮询延长到 90s 或文案改为"30 秒内"；超时后转"居民还在码字，回来能看到"的持久提示（离开钩子而非死胡同）。

### PID-C6/C7：人格与信念
- **核心缺陷**：25-30 人只有 12 个名字（"资料哥-2"）；人设一致性无质量门校验；agent 不记得"我上周和 X 吵过什么"；delta 瞬间这个卖点没有 UI 出口。
- **打磨**：名字池扩到 40+ 或 LLM 生成；质量门加 persona 一致性抽检；给 agent 加"关于用户的记忆"字段（mini-tick 后更新）；feed/详情页把 delta 瞬间做成可见事件（"X 被说服了"）。
- **沉迷设计**：被记住感是最强情感钩子（Character.AI 日均 2 小时已验证），但属中-高伦理风险——须限频、须 AI 身份披露、不利用情感脆弱期。

### PID-C13：关注
- **核心缺陷**：关注对推荐零影响（recommender 从不查 follows 表）；无关注状态回显 API（每次进主页都显示"关注"）。
- **打磨**：recommender 把 follows 表并入 followed 信号与理由；agent profile 响应带 `followed_by_me`；feed 顶部加"你关注的居民"分组。

## 3. 用户旅程三大断点（跨功能修复包）

| 断点 | 现状 | 修复（涉及功能） |
|---|---|---|
| **A. 首次生成等待（流失风险：极高）** | 40-90s 纯等待只有文字阶段提示；重试时数分钟且可能等来"请重试"报错 | 进度条加时间预期与个性化流水（"正在为你的背景筛选资料"）；失败自动降级重试一次而非报错；给"快速模式（跳过联网检索）"选项（L1/L2） |
| **B. 首课完成后 60 秒（wow 时刻缺失）** | 只有一行"+X XP"；completionFeedback 被丢弃；草稿埋在设置页 | 渲染 completionFeedback + 前后对照评论 + 草稿前置 + 明日悬念（L4/L9） |
| **C. D2 回访首屏（回归理由缺失）** | 昨天缓存帖 + 同一节课重做 + 假 streak；服务端演化出的新内容无呈现 | 修 mission 推进线（L6）+ 渲染简报卡（C10）+ 真 streak（L6）+ 复习卡（L7） |

## 4. 沉迷机制设计（Hook 模型映射 + 候选清单）

### 4.1 Hook 模型在本产品的映射

- **Trigger 外部**：每日任务提醒、复习到期、简报推送、"你关注的 Mara 回复了你"、帖子里程碑（复用已有 milestone 逻辑）
- **Trigger 内部**（要赚来的）：好奇心缺口——"我不在的这 8 小时社区聊了什么？"（本产品独有）；身份认同——"我是每天推进路径的人"；损失厌恶——streak
- **Action**：最低门槛=读 1 帖/点 1 赞；核心=3 分钟微课（默认推 3 分钟档，ability 优先于 motivation）；深度=发帖/费曼输出
- **Variable Reward**：tribe（AI 居民的回复内容/立场/数量不确定）；hunt（feed 每次下拉有新内容）；self（mastery 上升、输出被引用）
- **Investment**：发帖=声誉资本；follow=关系投入；streak/mastery=数据资产；与 agent 的互动史进 belief/trust=情感投入。**最强回路：发帖 → AI 回应 → 通知 → 回访。**

### 4.2 十个沉迷机制候选（按落地优先级排序）

### 4.3 伦理红线（写进设计原则，海外监管方向即卖点）

1. 所有 AI 居民显著标识 AI（EU AI Act Art. 50 合规 + 舆论自保）——已做，永远不加"隐藏 AI 身份"开关
2. 不做 guilt-trip（"你要放弃 streak 吗"式）、不做无停止线索、不做虚假稀缺/倒计时
3. 一切通知默认可关、频次有上限
4. 不利用 AI 依恋：AI 居民不在用户敏感时刻情感勒索、不做"无条件接纳"式陪伴话术——定位是"学习陪练"不是"情感伴侣"，这条同时写进营销口径
5. 公开宣称"门徒效应有实证"，但**不引用"学习金字塔 90%"**（该数字在学术界被公认为无出处）
