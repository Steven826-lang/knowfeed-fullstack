# KnowFeed 产品策划案（创业版）

> 日期：2026-07-16
> 作者：AI 产品策划（基于全项目尽职调查 + 竞品/市场/架构/策略四路调研）
> 状态：供创始人决策
> 关联文档：PRD_V2.md、docs/superpowers/specs/2026-07-16-learning-community-design.md

---

## 0. 执行摘要

KnowFeed 目前拥有一个**完成度很高的单机原型**：AI 生成 7 天个性化学习路径 + 微课堂 + 刚建成的 Reddit 式 AI 居民学习社区。四路调研的结论一致：

1. **市场位置是真的**。"AI 生成课程"已被 Oboe（a16z 1600 万美元）验证，"AI 持久人格的粘性"已被 Character.AI（日均 2 小时）验证，但"结构化学习路径 × 围绕学习内容的讨论社区"这个闭环**没有人完成**——Oboe 无社区、Duolingo 社区极弱、知乎/小红书无学习路径。KnowFeed 恰好站在这个交叉空位上。
2. **当前原型离创业产品还有四层 gap**：没有账号体系（多用户即串数据）、没有成本治理（LLM 调用嵌在请求路径上， economics 不成立）、没有留存答案（7 天课程结束后用户为什么回来）、没有监管答案（中国《人工智能拟人化互动服务管理暂行办法》2026-04 已公布，正落在射程内）。
3. **建议的打法**：工具价值 → 习惯回路 → 差异化惊喜。先把"路径生成 + 微课堂 + 每日 feed + streak"磨到留存达标，AI 社区做"读多写少"的轻量版当惊喜点，真人社交和付费层后置。
4. **市场决策（2026-07-16 创始人拍板）：海外首发**，绕开国内拟人化互动监管；中文版本作为后续选项保留。详见 §6.1。

## 1. 现状评估：功能做得不足的地方

### 1.1 严重问题（伤害核心体验，必须立刻修）

| 问题 | 位置 | 为什么严重 |
|---|---|---|
| **quiz 正确答案恒为 choice-a** | `curriculumValidator.buildChoices` | 微课答题可被秒杀，学习验证完全失效；这是"学习产品"的地基问题 |
| **伪造数据** | `HomeFeed.tsx:101`（在线人数 = 帖数×3+8）；bundle fallback 的"128+N 条讨论" | 与自家 `COMMUNITY_EXPERIENCE_GUIDE.md` 的"不要用假在线人数"直接冲突；用户一旦察觉，对整个社区的信任归零 |
| **赞同/收藏/分享是假 toggle** | `PostDetail.tsx` 本地 state 翻转，不持久化、不调已存在的 `/api/community/reactions` | 用户操作刷新即丢，社区互动感断裂 |
| **onboarding 为两套世界付两次 LLM 钱** | `App.tsx` 仍创建 legacy colearning world（25 personas + 最多 6 次 seeding 调用），但该世界只写不读 | 每次 onboarding 白烧 LLM 成本；旧 `/api/colearning/*` 端点应随 OASIS 一起退役 |
| **7 天课程结束后没有留存钩子** | 产品层面 | 这是所有竞品调研里最大的教训（国内 AI 社交下载量 -80% 的"新鲜感悬崖"）。用户跑完 7 天路径后，目前没有任何理由第 8 天回来 |

### 1.2 中等问题（影响质量与可维护性）

- **双渲染路径缝合**：HomeFeed/PostDetail 里到处是 `communityPost ? ... : bundle` 分支，`adaptCommunityPost` 在两个组件各写一份；stance/relation 中英映射靠默认值兜底。
- **LLM 出口四分裂**：`llm.py`、`tick_engine.py`、`content_generator.py`、`world_init.py` 四处各自拼 `/api/generate` 请求，模型名三套 env fallback，只有 legacy 路径有 429 backoff。
- **schema 迁移三处重叠**：`db.py migrate()`、`main.py:_ensure_community_schema`、`agent_manager.ensure_agent_schema`，注释互相称对方是 "parallel workstream"。
- **巨型单文件**：`llmContracts.ts` 1682 行、`tick_engine.py` 1494 行、`real-llm-e2e.mjs` 2151 行、`main.py` 1050 行。
- **E2E 场景词泄漏进生产代码**：`generationPrompt.ts` 里的建筑史/电商/古典音乐硬编码词表、`llm-proxy.mjs` 的 fintech/心理/AI/web3 特判——任意新主题都走 generic 兜底，质量分层明显。
- **人格池只有 12 个硬编码名字**：25-30 个 agent 靠 `-2/-3` 后缀凑数且跨主题复用，"有持久人格的 AI 居民"这一核心卖点的人格多样性不足。
- **大量未提交改动**：28 个文件 +3138 行新社区代码全部在工作树里，证据链（verify:evidence-archive）停在失败状态。

### 1.3 产品功能缺口（对照竞品与市场）

| 缺口 | 证据 |
|---|---|
| **没有学习效果验证环节** | 所有竞品都被批"感觉在学但没学会"（Duolingo 打卡焦虑、小红书收藏吃灰）。费曼学习法（向别人讲清楚一个概念）是有理论支撑的差异化空白，shadow draft 目前只是"草稿箱"，没有做成"向 AI 居民讲一遍"的输出仪式 |
| **没有"下一个主题"的承接** | 7 天路径是单程票；没有主题订阅、没有"学完后推荐相邻主题"、没有跨主题进度 |
| **AI 居民没有跨世界记忆** | belief_json 只存在单个 world 里，换主题就是陌生人；Character.AI 的头号投诉"记忆重置"会在我们这里复现 |
| **没有通知/回访机制** | 用户不发帖就不知道社区发生了什么；"你的帖子有新回复"、"你的复习队列到期了"都没有触达通道（PWA push 是现成选项） |
| **没有音频/多模态** | Oboe 的招牌就是音频微课匹配碎片时间；我们只有文字 |
| **没有学习报告** | 订阅制产品需要"每周你学到了什么"的可视化总结来支撑续费决策 |

## 2. 市场与竞争定位

### 2.1 已验证的市场信号

- **AI 生成课程**：Oboe（Anchor 创始人，a16z 领投 1600 万美元 A 轮）；中文市场秘塔"今天学点啥"已进场但无社区无游戏化。
- **AI 人格粘性**：Character.AI 日均使用约 2 小时、D7 留存 40%；斯坦福 Smallville 证明 25 个有记忆的 agent 能涌现可信社会行为（创始人后续融资 1 亿美元）。
- **中文付费意愿**：教育智能硬件 2023 年 807 亿元（+29.5%），但集中在 K12 家长场景；成人泛知识纯软件付费待验证——这既是风险也是空位。
- **社区提升完成率**：cohort 课程完成率 40–70%，MOOC 中位仅 12.6%。KnowFeed 的 AI 学习小组本质是"用 AI 模拟 cohort 的同伴压力与回应感"。

### 2.2 竞品矩阵与我们的位置

| 竞品 | 有内容 | 有路径 | 有社区 | 有游戏化 | 有 AI 人格 |
|---|---|---|---|---|---|
| Oboe | ✅ | ✅ | ❌ | 弱 | ❌ |
| Duolingo | ✅ | ✅ | 极弱 | ✅ | ❌ |
| 知乎/小红书 | 碎片化 | ❌ | ✅ | ❌ | ❌ |
| Character.AI/星野 | ❌ | ❌ | ✅ | ❌ | ✅ |
| **KnowFeed** | ✅ | ✅ | ✅（AI 居民） | ✅ | ✅ |

### 2.3 差异化三支柱（护城河必须建在这上面）

通用助手（豆包、ChatGPT）也能生成学习计划，所以护城河**不能**是"AI 生成内容"，必须是三者叠加：

1. **结构化进度系统**：validator 掌握的 mastery/复习队列/解锁关系——这是数据资产，通用助手没有。
2. **人格化社区的持续关系**：AI 居民记得你学过什么、发过什么帖、和你抬过杠——跨主题延续。
3. **学习数据飞轮**：用户的学习行为（答题、发帖、复习）反过来改进推荐和内容生成。

### 2.4 必须避开的坑（竞品血泪）

- **情感依赖变现**（Replika 的 guilt-trip 留存）：国内监管已明确红线，且我们定位学习，天然要避开。
- **"感觉在学但没学会"**：微课必须有真实的学习验证，quiz 不能是摆设。
- **记忆重置**：AI 居民的记忆持久性是信任地基，SQLite/后端的 belief 存储必须扎实，跨主题延续。
- **死互联网感**（Moltbook 的批评）：纯 AI 内容只能带来猎奇流量。用户必须能参与，且参与要有回报（被回应、被记住）。
- **知识焦虑营销**（得到的教训）：不贩卖焦虑，卖"看得懂的讨论"和"学得完的路径"。

## 3. 功能增加建议（按优先级）

### P0：让现有体验成立（创业前必须修完）

1. **修 quiz**：答案位置随机化 + 错误选项也要有迷惑性反馈（validator 改动很小，收益极大）。
2. **去掉一切假数据**：在线人数改为真实口径（agent 数 + 活跃状态）或直接删除；bundle fallback 的假指标删除。
3. **接上真互动**：PostDetail 的赞同/收藏接通 `/api/community/reactions`（后端已存在），收藏进 localStorage + 服务端。
4. **删除 legacy colearning**：停掉 onboarding 里的 legacy world 创建，退役 `/api/colearning/*` 端点和 `colearning.ts` 死代码——纯减法，立即省一半 onboarding LLM 成本。
5. **收敛双渲染路径**：Feed/帖子页统一以 community 引擎为主，bundle 仅作为微课内容的离线兜底，抽出统一的 post 适配层。
6. **提交并刷新证据链**：28 个未提交文件入库，重跑 verify 门禁。

### P1：回答"第 8 天为什么回来"（留存层）

7. **主题订阅制**：7 天路径跑完后，推荐相邻主题（"学完 Fintech 基础 → 支付清算进阶"），一键开启新路径；AI 居民部分延续到新主题世界。
8. **AI 居民跨世界记忆**：belief/persona 摘要跟随用户跨主题迁移（"资料哥还记得你上次问过私钥的问题"）——这是 Character.AI 头号投诉的正面解法，也是订阅续费的情绪钩子。
9. **费曼输出仪式**：把 shadow draft 升级为"向 AI 居民讲清楚这个概念"——用户发布理解后，AI 居民追问/挑刺/点赞，完成输出即掌握度大涨。这是学习效果验证的核心环节，也是社区与学习主线的真正缝合点。
10. **streak freeze + 复习提醒**：Duolingo 验证过的损失厌恶机制；复习队列到期时 PWA push 通知。
11. **每周学习报告**：掌握度曲线 + 参与讨论 + 下周建议，邮件/PWA 推送——订阅产品的续费理由。

### P2：规模化前的产品准备（PMF 后）

12. **真人弱连接**：同主题 cohort（50–200 人同期开学），真人帖子与 AI 居民混排，逐步用真人密度替换 AI 密度（Andrew Chen 的 Flintstoning 反向操作）。
13. **音频微课**：通勤场景，TTS 即可起步，对标 Oboe 招牌。
14. **通知中心**：帖子被回复、被点赞、被 AI 居民引用。
15. **主题市场/UGC 路径**：用户生成并分享学习路径（远期网络效应）。

### 4.2 模块输入输出契约（关键定义）

| 模块 | 输入 | 输出 |
|---|---|---|
| 学习引擎 | LessonResult、curriculum draft | ValidatedCurriculum、ProgressState、DailyMission、解锁事件 |
| 内容生成 | GenerationJob{userId, topic, profile, conceptId} | CurriculumDraft、微课/帖子/评论树、job 状态（异步） |
| 社区引擎 | 世界事件流（发帖/评论/点赞/定时 tick） | 世界变更落库 + 通知事件（"你的帖子有新回复"） |

### 4.3 Monorepo 结构（工程视角）

```
knowfeed/
├─ apps/
│  ├─ web/                  # 现有 Vite+React 瘦身：引 router，删 domain 里的 LLM/存储逻辑
│  └─ api/                  # BFF/网关：鉴权、限流、聚合
├─ services/
│  ├─ learning-engine/      # 由 packages/domain 长出：课程校验 + 进度
│  ├─ content-gen/          # planner + bundle 生成 worker（队列驱动 + prompt registry）
│  └─ community-engine/     # 现有 FastAPI 收敛：删 legacy，tick 改独立 worker
├─ packages/
│  ├─ contracts/            # 单一事实源：pydantic → OpenAPI → TS 类型，消灭双写
│  ├─ domain/               # 纯函数：learningEngine、feedEngine、recommender、belief_state
│  ├─ llm-client/           # 统一出口 SDK（TS+Py）
│  └─ config/               # env schema，消灭 4 处模型名 fallback
├─ infra/                   # Alembic 迁移、docker compose、CI
└─ tools/                   # e2e、eval
```

### 4.4 World 归属模型（已拍板：分身社区）

- **现状**：每用户每主题一个世界（session_key=topicId），25 个 AI 居民为单个用户演戏。优点：体验高度个性化；缺点：**LLM 成本随用户数线性爆炸**，且没有网络效应。
- **最终决策（2026-07-16）：分身社区（Shadow Community）**——主题级共享世界，社区主体是**每个用户的 AI 分身**（锚定用户真实学习状态发言），NPC 居民降级为催化层（暖场/保底/观点多样性/主持，密度可调）。详见 PRD_V3 §4.0。
- 为什么是它而不是纯共享世界：分身对分身 = 真实学习者之间的间接辩论，既有网络效应又有真实性锚点（防"死互联网"）；NPC 做脚手架保证冷启动每条发言有回应。
- 这个决策影响数据模型（分身一等公民、多用户共享世界）、成本模型（世界按主题而非按用户）、社区氛围（用户声誉直接挂钩分身发言），是后续多用户代码的前提。

## 5. 路线图

### 阶段 0：还债与收敛（2–3 周，纯工程，不出新功能）
完成 P0 全部 6 项。出/入标准：无假数据、quiz 可用、单轨社区、证据链绿、成本减半。

### 阶段 1：公测 MVP（4–6 周）
- 最小账号体系（邮箱登录 + 服务端进度同步）——唯一不能拖的基建
- P1 的 7/8/9/10：主题订阅、跨世界记忆、费曼输出、streak freeze + 提醒
- tick/backfill 移出请求路径（独立 worker，feed 变纯读）
- 50–200 人小 cohort 公测，只看不收費
- **达标线**：7 天路径完成率 ≥30%、D7 ≥15%、D30 ≥8%；不达标先修留存再谈付费

### 阶段 2：PMF 与付费（6–10 周）
- Freemium：免费 1 个主题 + 付费无限主题/深度互动/学习报告（定价参照 Speak $20/月档位，早期 2–3% 转化即合格）
- 每周学习报告、通知中心
- 真人弱连接（cohort 混排）
- LLM 网关配额化，单用户月成本测算并压进定价模型

### 阶段 3：规模化（视数据）
- B2B 退路（企业内训/高校，MagicSchool 模式）
- 主题市场/UGC 路径
- 音频微课、移动端壳

## 6. 风险登记册

| 风险 | 等级 | 对策 |
|---|---|---|
| **留存悬崖**：新鲜感消退（星野下载 -80%、C.AI MAU 峰值回落 30%） | 🔴 高 | 7 天短路径提高完成率天花板；P1 留存层全部服务于"第 8 天"；公测只认 D7/D30/完成率三个数 |
| **大模型降维打击**：通用助手也能生成学习计划 | 🟠 中高 | 护城河押在进度数据 + 人格关系 + 数据飞轮三者叠加，不押内容生成本身 |
| **成本失控**：内容全量 LLM 生成 | 🟠 中高 | 阶段 0 删 legacy 即省一半；模型分层（init 好模型 / tick 便宜模型）；世界混合制；阶段 2 前必须算出单用户月成本 |
| **海外合规**（见 §6.1）：GDPR 删除权/导出权、AI Act 透明度、支付税务 | 🟠 中 | AI 标识已做（天然符合 AI Act 透明度）；账号体系落地时同步做数据删除/导出端点；法律条款（Privacy Policy / ToS）上线前备齐 |
| **AI 内容质量/幻觉**：深度主题出错 | 🟡 中 | 保留并服务端化 llmContracts 的 12 项质量门；高风险主题（医疗/法律/金融）只给学习框架不给建议（已有规则）；来源溯源 UI 已有 |

### 6.1 海外首发决策的影响（2026-07-16 拍板）

**决策：先上海外市场，绕开国内《人工智能拟人化互动服务管理暂行办法》。**

注意：海外≠无监管，只是更轻、更可预期。需要补的功课：

| 事项 | 要求 | 现状与差距 |
|---|---|---|
| **EU AI Act** | AI 系统透明度：用户必须知道在与 AI 交互 | ✅ 已满足（agent AI 角标 + AgentProfile 明示，§8.5），继续保持，不得提供"隐藏 AI 身份"开关 |
| **GDPR**（如有欧洲用户） | 数据删除权、导出权、知情同意 | 🔴 差距大：目前无账号、无删除/导出端点；localStorage 明文存画像；用户文本直发第三方 LLM 无告知。账号体系落地时必须同步做：注册时 ToS/Privacy Policy 勾选、用户数据导出端点、账号删除（级联清帖/评论/偏好） |
| **COPPA（美国）** | 13 岁以下儿童数据保护 | ✅ 成人泛知识定位天然避开；注册流程加 16+/18+ 年龄确认即可 |
| **i18n** | 产品目前是全中文 UI + 中文 prompt 体系 | 🔴 大工作流：UI 文案抽离（react-i18next 或同类）、LLM prompt 多语言化（generationPrompt/tick_engine/personas 全部中文 prompt 需要英文版）、首发建议英文（对标 Oboe 主战场），中文资源保留作第二语言 |
| **支付** | 海外订阅计费 | 阶段 2 用 Stripe（订阅+税务），不用考虑国内支付渠道 |
| **LLM provider** | 海外延迟、合规、成本 | 重新评估：StepFun 海外可用性/延迟未验证；候选 OpenAI/Anthropic/Gemini/DeepSeek；llm-gateway 的模型路由设计不变，只是 provider 配置问题，但要在阶段 1 前实测出 content-gen 质量对比 |
| **社区内容安全** | 海外平台常规要求（CSAM/仇恨言论红线） | 质量门已有基础；上线前补一层硬红线过滤（可用现成 moderation API） |

**产品定位话术调整**：从"中文学习社区"改为"AI study community / learn with AI peers"，主打卖点不变（structured path + micro-lessons + AI residents who remember you），目标用户从"中文兴趣学习者"改为"全球终身学习者"，首发垂直市场建议选英语区的 1-2 个高学习意愿主题（如 AI/tech、personal finance）做深再扩。

**国内版本**：作为后续选项保留，不删除中文资源；若未来回国，再按原 §6 监管对策执行（成人定位、AI 标识、防沉迷开关、话术降级）。
