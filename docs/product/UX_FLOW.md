# KnowFeed UX Flow

日期：2026-06-10
当前交付校准：2026-06-18

## 1. 体验原则

- 首屏像社交媒体，不像课程后台。
- 每天只有一个明确主任务。
- 用户可以从“今日任务”或“帖子好奇心”进入学习。
- 学完必须回到 Feed 或评论区，马上看到知识的用途。
- 不用大段解释产品功能；用实际内容让用户理解。
- 真实 LLM 生成内容是主体验；fallback 只用于 demo continuity 和故障降级，不能被设计成主要内容路径。
- 移动端是首要体验面，iPhone safe area、底部导航、长等待状态、输入框和来源展开都必须先在手机视口成立。

## 1.1 当前 UX 交付状态

当前实现已经覆盖主线体验：

- Onboarding 收集主题、背景、负偏好、目标、每日时间、学习深度和信息流语气。
- Onboarding 的生成态会分阶段显示“理解目标 / 联网检索 / 规划路径 / 生成讨论”，失败时保留用户输入并给出重试入口。
- First-run 用户会先看到 7 天学习路径预览，再进入 feed。
- Feed 首屏先展示生成的社区讨论；今日任务和当前学习路径是下方辅助入口，不能压过真实 LLM 内容。
- 社区身份必须先像真实网名和 handle，再用轻量“视角” metadata 解释作者位置；不要把 `stance` 或 `role` 设计成主要身份。
- 顶部栏不再放一个不可用的搜索按钮。
- Post detail 支持本地回复和针对单条评论的回复上下文；展开写回复时输入区不再 sticky 遮挡评论。
- Micro-lesson 完成后会回到评论区，并显示完成反馈。
- Settings 里的 AI 学习分身草稿可以编辑、拒绝、批准，并在批准前展示依据；重置本机原型进度需要二次确认。
- Path preview、feed、post、lesson、shadow surfaces 都接入了来源说明；web research 时 compact 状态会先露出一个研究/来源锚点，展开后用中文解释“网页资料辅助的 AI 生成 / 已接入网页资料 / AI 规划路径”，同时保留 `Research brief + LLM`、`Research: web`、`Path: planner` 等机器证据字符串。
- iPhone/PWA baseline 已有 `viewport-fit=cover`、manifest、icon、`100dvh` 和 safe-area padding。

这些实现仍然不能直接等于交付完成。最终 UX 证据必须来自真实 `Research brief + LLM` 输出，而不是 fallback 或历史截图。

## 1.2 当前 UX 缺口优先级

P0 交付阻塞：

- 真实 LLM 生成路径还缺 fresh visible-browser 证据。Kimi WebBridge 已可用，但当前只有 fallback mobile UX 和局部 cached Research + LLM 证据；最终必须捕获真实 `Research brief + LLM` 的 onboarding -> path -> feed -> post/comments -> lesson -> shadow -> reload -> map 路径。
- 长时间生成状态和失败重试已经有本地 UI 覆盖，但还缺真实海外 provider 慢请求下的可视浏览器证明；下一轮 Kimi/Chrome 验证要专门截取这个阶段进度。

P1 体验打磨：

- 来源说明的内部标签已改为中文优先、证据字符串保留的双层展示；下一步要用真实 `Research brief + LLM` 浏览器路径验证这些标签在 feed、post、lesson、shadow 长内容里都可扫读。
- 评论区/回复区需要继续验证 exactly 8 个 LLM 设计的 topic-fit 社区 agent 和 exactly 3 条模型回复在手机屏幕上是否可扫读，尤其是昵称、handle、轻量“视角”、正文和回复层级；`stance` / `relation` 只做内部 metadata，不应显示成用户可见标签。
- 评论区还需要验证 `displayName` 是否自然、随机、像网名，而不是 `topic + 实践派/资料党/挑刺员`。生成契约和验收细节见 `docs/product/COMMUNITY_EXPERIENCE_GUIDE.md`。
- AI 学习分身的“依据”需要在移动端确认不会被编辑框或批准按钮挤掉；批准前必须一直可见。
- Bottom nav 和顶部 source strip 在长内容滚动时不能遮挡 CTA、评论回复目标或 shadow 操作；回复输入框 sticky 遮挡已经本地修复，仍要在手机浏览器复验。

P2 后续增强：

- 第二天回访流程还主要停留在需求描述，需要真实状态/内容证明。
- 桌面布局应保持可读，但不是当前第一优先级；桌面证据服务于 expanded-full gate，而不是替代手机体验。

## 2. 首次用户流程

```text
欢迎/定位
-> 选择领域
-> 填写背景
-> 填写目标和每日时间
-> AI 正在研究和规划
-> 7 天路径预览
-> 首页 Feed
```

### Step 1: 选择领域

UI 应该像搜索/发帖输入，而不是课程目录。

示例 prompt：

- “我想了解 Fintech”
- “我想看懂心理学里的依恋理论”
- “我想从产品视角理解 AI Agent”

推荐 chips：

- AI 入门
- Fintech 入门
- 心理学入门
- Web3 入门
- 电影史
- 经济学

### Step 2: 填写背景

短输入 + 快速选项。

字段：

- 我是谁：普通兴趣用户、工程师、产品经理、学生、创作者。
- 我已经懂什么。
- 我不想看到什么：太数学、太技术、太学术、太鸡汤。
- 这个负偏好必须进入 `LearnerProfile.avoidedStyles`，并被 planner/generator prompt 当作硬约束，而不只是 UI 文案。

### Step 3: 目标和时间

字段：

- 学习目标：看懂讨论、能聊天、做项目判断、写观点。
- 每日时间：3、5、10、15 分钟。
- 路径长度：默认 7 天。

## 3. 生成路径流程

生成态不是普通 loading。它应该让用户感觉“AI 正在替我整理世界”。

当前展示阶段：

1. 理解目标：保存主题、背景和负偏好。
2. 联网检索：抓取真实资料锚点。
3. 规划路径：让 AI 生成学习路线。
4. 生成讨论：生成首页微课和评论区。

失败时必须保留表单内容，并提供“保留表单并重试”。这个状态不能把 fallback 当作主体验解释给用户。

完成后显示 7 天路径：

- 每天一个主题标题。
- 每天一个“你会看懂什么讨论”。
- 路径页必须显示可展开的生成来源链路、research 锚点和资料来源，让用户知道这条路径来自 research / planner / generated content，而不是普通静态目录。
- 可以直接开始 Day 1。

## 4. 首页结构

首页是双入口，但内容优先级必须像信息流而不是课程后台：

1. 生成的社区主帖和评论预览。
2. 今日任务卡。
3. 当前学习主题和路径预览。

今日任务卡负责习惯：

- 今日学什么。
- 预计几分钟。
- 为什么现在学。
- 直接开始按钮。

Feed 负责好奇：

- 首屏第一张内容卡必须是当前 bundle 的生成主帖，并带来源说明。
- 不能伪装成可以输入新话题的 composer。
- 评论/争议摘要。
- “看懂这条讨论”按钮。
- 下一阶段钩子。

## 5. 帖子详情

帖子详情像评论区，不像课程页。

结构：

- 主帖。
- 评论筛选：热门、反方、正方、最新。
- 高热评论。
- AI 账号互相反驳。
- 本地回复输入，让用户写下一句理解或追问；从单条评论点回复时，输入框必须显示回复目标和引用上下文。
- “学完这个概念再回来”入口。

评论风格：

- 允许尖锐。
- 允许争议。
- 允许挑刺。
- 不能人身攻击。
- 不能攻击身份群体。
- `stance` 和 `relation` 是结构化 metadata，不是正文开头；评论正文不能写成“赞成：”“追问：”这种 agent 回答槽位。
- displayName 是网名层，role 是轻量“视角”层。前端不应让 role badge 压过昵称和正文。

## 6. 微课

微课像多邻国短任务，不像文章。

结构：

1. 30 秒 hook。
2. 一个核心解释。
3. 一个类比。
4. 一个选择题。
5. 一句主动回忆。
6. 反馈。
7. 回到 Feed/评论区，并在评论区顶部看到本次完成反馈。

必须短，不能变成长文阅读。

## 7. 学习分身

学习分身不是聊天伙伴。

它的第一版职责：

- 根据用户刚学的内容起草评论。
- 根据用户理解质量调整语气。
- 帮用户从“看懂”走向“能说一句”。

分身页必须有：

- 草稿。
- 自信度。
- 依据的学习记录，并且要出现在编辑框和批准操作之前。
- 批准发布。
- 编辑/拒绝。

## 8. 回访流程

第二天用户回来时：

- 直接看到今日任务。
- Feed 里出现昨天知识的复习评论。
- 新帖预告下一阶段。
- 如果昨天没完成，今日任务仍然低压力，不惩罚过重。

## 9. UI 不应该出现的形态

- 大型课程目录。
- 讲师卡片。
- 传统论坛版块。
- 群聊房间。
- 游戏化仪表盘压过内容。
- 纯聊天机器人首页。
