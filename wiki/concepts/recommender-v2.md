# 推荐系统 v2

> 依据 [[social-platform-playbook]] §3 对 v1 五信号推荐器的缺口诊断，P0 随本 sprint 落地（PRD FR-C1）。v1 实现见 [[learning-community-engine]] 的 recommender 节。

## v1 基线（recommender.py 现状）

兴趣 30% / 热度 25% / 新鲜 20% / 多样性 15% / 学习价值 10%；`get_feed` cursor 分页、`rerank_with_diversity` 同作者不相邻、`reason_for_post` 理由标签。

## 四个结构性缺口与修法

| 缺口 | 行业证据 | v2 修法 |
|---|---|---|
| **没有负反馈通道**（最严重） | X 开源算法：block −3.0、report −5.0，负信号绝对权重大于正信号；用户容忍平庸推荐，但会离开持续惹恼他的平台 | 新增负反馈项（划过 / 不感兴趣 / 屏蔽分身），权重约 **−20**，对"主题×作者"快速衰减 |
| **没有探索配额** | TikTok 流量池：每条新内容保底 200-500 人试镜；Reddit 新帖 90% 死在 New 队列 | 每条新帖、每个新分身**保底 N 次试镜曝光**，互动率达标进主流量；新鲜度从分数项改为"每屏 2-3 个新帖保底位"配额制 |
| **多样性不该是排序分** | X：author diversity 在排序后的重排层做硬约束 | 多样性移出排序分，进重排层硬规则 |
| **热度信号形态** | Reddit 刷票根源是"早期速度进主排序" | 原始计数 → **互动率**（Wilson 下界或 Beta 后验均值）；早期速度只在爬坡阶段起作用；热度权重 25→15 |

## 重排层硬约束

- 同作者相邻 ≥3 条间隔
- 单 feed 同作者上限
- **真人 / 分身 / NPC 三类配比控制**（KnowFeed 特有维度）：神评/置顶位人类 ≥50%——AI 分身是天然"神评制造机"，不配比就会剥夺人类存在感通道（详见 [[shadow-community-model]] 存在感保护）

## v2 信号表

| 信号 | v1 | v2 | 说明 |
|---|---|---|---|
| 兴趣匹配 | 30 | **35–40** | 拆长期（学习路径主题，稳定）+ 短期（近 48h 行为，实时）双轨 |
| 热度 | 25 | **15** | log 尺度 + 互动率口径，降权抑马太 |
| 新鲜 | 20 | **5–10** | 配额制保底位，不靠分数 |
| 多样性 | 15 | **移出** | 进重排层硬约束 |
| 学习价值 | 10 | **10–15** | 兼作新内容探索的先验分（高学习价值新帖获更多试镜）——区别于娱乐平台的目标函数轴 |
| 负反馈（新增） | — | **−20** | 划过 / 不感兴趣 / 屏蔽 |

## 轻量探索（不用 ML 框架）

- 每个"主题×分身"组合维护 **Beta(α, β)** 后验（α=正反馈+1，β=负反馈+划过+1）
- **Thompson 采样**决定探索顺序——几行代码，天然解决"新分身无历史不敢推"

## 冷启动的结构性优势

- 传统社区 cold start 是"没真人就没内容"；KnowFeed 的 atomic network 最小值 = **1 个真人 + N 个 AI**，单用户第一天就有完整社区体验
- NPC + 分身 = "合法合规的 Reddit 种子账号策略"（Reddit 当年要偷偷装假用户，我们是公开明示的产品特性）
- 原子网络切分维度是学习主题：先把一个主题（如 AI/LLM）的讨论密度打穿再扩，不要全主题铺开

## 验收指标（PRD FR-C1）

点"不感兴趣"后同类内容显著减少；新帖均获保底曝光；单 feed 同作者不出现 3 连；置顶位人类占比达标；可加载第 2 页且不重复；推荐理由映射 concept 标题（禁止渲染原始 concept_id 哈希）。
